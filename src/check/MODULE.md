# src/check/

## Purpose
`wj check`: the compiler front end as a standalone checker. Lex, parse, lints, surface-syntax findings, name resolution, conservative semantic checks, analyzer, numeric inference and IR solvers; no cargo, no rustc, no generated code.

## Inputs/Outputs
In: a `.wj` file or project directory. Out: `Checked { report, sources }` in the shared diagnostics schema.

## Invariants
- Never invokes cargo or rustc.
- Semantic checks are conservative: a program the build accepts must pass (`check_has_no_false_positives_on_the_build_corpus`).
- Caches never change diagnostics (gate: tests/check_cache_differential_test.rs, with a recorded mutation check in ADR-0020 round 3 rung 4). Two layers, both under `<project>/.wj-cache/`:
  - `cache.rs`, whole run: SHA-256 over all paths + contents, manifest, lock file, dependency sources, plus the compiler build and the ambient `.wj.meta` sidecars (`ambient.rs`); any change anywhere is a miss.
  - `file_cache.rs`, per file: the analysis phase (analyzer, numeric inference, IR solvers) reads one file and the stdlib only, so it is keyed on path + SHA-256 of the text, under a header of build + ambient digest. Resolution, effects and the semantic index always run. If the analysis phase ever reads another file or project signatures, that input must join the key.
- Stored cache text names the project root only as the placeholders `{PROJECT_ROOT}`, `{PROJECT_ROOT_ABS}`, `{PROJECT_ROOT_REAL}` (one per spelling) (`cache::mask_root`/`unmask_root`), cache keys and file names hash project-relative paths, and the ambient digest does not include the working directory: a copied or moved checkout carries no absolute path and keeps its hits (gate: tests/check_cache_location_free_test.rs).
- `run_cache.rs`, the check before `wj run --interpret` (any program, lone scripts included): key = SHA-256 of the compiler build by content (`shared_cache::compiler_key`), the baked stdlib/runtime fingerprint, every `inputs` entry (paths + texts), `--no-lint`, the error format, the working directory, the entry spelling and the `WJ_*`/`WINDJAMMER_*` environment; the `.wj.meta` digest is verified on load. Only clean outcomes whose width prediction read only the sources are stored, with the exact stderr replayed on a hit; the store (`<cache root>/runs`) is injected by `cli::check`. Gate: tests/run_check_cache_test.rs.
- `ambient.rs`: the numeric inference reads `.wj.meta` sidecars relative to the working directory; their digest is part of both keys, and a walk over budget disables caching for that run.
- `--fix` applies only machine-applicable fixes and refuses results that no longer parse.

- `rust_calls.rs` (ADR-0026): calls into a Rust crate with a surface are checked against it (`WJ0050` undeclared or malformed surface, `WJ0013` arity, `WJ0003` literal kind); `rust_crate_calls` is the subset `wj build` stops on. Calls into a crate with no surface: `W0014` with the `wj rust-surface` command; a skipped generated function: `WJ0050` with the generator's reason. `std_calls.rs`: `WJ0002` for a call to a function a std module does not provide (`strings.index_of` after `use std::strings`; locals shadow the module name; gate tests/std_calls_check_test.rs). `rust_surface_health.rs`: `W0015` when a generated surface names another crate version than `Cargo.lock`. Surface files (hand-written and cached) and lock files are inputs of the result cache.

- `semantic/elements.rs` (WJ0003, char against text): element kinds of `for` and `let` bindings read from declarations (`std/strings.wj` return types via `stdlib_surface::std_functions::declared_return`, `String` methods of `std/rust_core.wji` via `typing::CoreSurface`); `ch == "?"` on a `char` is rejected with a `'?'` fix; unknown kinds are never judged. Gate: tests/diagnostics/cases/char_*.
- `semantic/checker/iter_use.rs` (WJ0035, ADR-0039 decision H): a lazy iterator used where a list is needed (index or slice, `len`/`is_empty`/`first` and other list-only methods, a `Vec` parameter, return, field or annotated `let`, comparison with a list, `${it:?}`, a bound iterator used twice). One code, span and machine-applicable fix (`.collect()` on the `let` or before the use; `.count()` for `len`, `.next()` for `first` on a single-use binding), shared by `wj check`, `wj run --interpret` and `wj build`; the interpreter's `len`/`is_empty`/`contains` on an iterator is a defensive error with the same code. Gates: tests/diagnostics_oracle/check/iter_as_list/ (one case per use kind), tests/iter_as_list_gate_test.rs (G8).
- `match_variants.rs` (WJ0003): a `match` whose arm patterns are the other wrapper's variants (`Some`/`None` against a `Result`, `Ok`/`Err` against an `Option`), where the scrutinee's type is declared (project fn return, `stdlib_surface::std_functions::returns`, a local bound once, a parameter type); the fix rewrites the variant. Gate: tests/match_variant_pattern_test.rs, tests/diagnostics/cases/match_*.
- `moves.rs` (ADR-0030, WJ0007): uses after a move predicted from the Rust generated in the per-file analysis phase. `widths/` (ADR-0033, WJ0003): a walker over generated Rust that finds two integer widths that must be one type, `String` against `&str`, or a value where a reference is required (drift families A, B, C), only where both types are certain; pure text in, clashes out. The driver (`cli/widths_gate.rs`) runs it on the build's emitted Rust, because the in-process generator's widths differ from the build's. Gates: tests/move_prediction_test.rs, tests/width_prediction_test.rs (precision scans with rustc as the oracle, pinned lists).
- `local_mut/` (ADR-0002, WJ0051): local bindings changed without `mut`, over the whole program at once (two analyzer passes with all files' signatures, then the IR solver: `facts.rs`); a method changes its receiver when the solver gives it `&mut self` or `std/rust_core.wji` declares `&mut self`; types of locals from declarations only (`types.rs`); the scoped walk (`walk.rs`); the declaration's text position for the fix (`decl.rs`). `local_mutability(path)` is the same report for `wj build`, `wj run` and `wj fix`. Gate: tests/local_mutability_test.rs.
- `taint/` (ADR-0009, WJ0173): untrusted data reaching a command, a file path to write or SQL text. `flow.rs` walks every function with symbolic parameters, summarises (result origins, parameters that reach a sink) and iterates the summaries to a fixed point, so a flow through helpers, methods and recursion is seen; `catalog.rs` holds the source and std-sanitizer rows and reads the sinks from the effect table (`ir::effect_facts::sinks`); `mod.rs` turns findings into diagnostics (span on the sink, second span on the source, a help line naming the source and the remedy). `/// wj-taint: sanitizer` marks a function whose result is safe; `/// wj-taint: trusted(<reason>)` reports nothing inside a function (the reason is required). The walk is bounded: wrapping depth, parameter paths and origins per value are capped (flattened past the cap), loops nested more than three deep are walked once (gate: scripts/wj/build_ceiling_gate.wj over tests/perf_ceiling). `may_flow` skips the whole walk exactly when no source or no sink call exists in the program (ADR-0009 amendment; gate scripts/wj/check_cost_gate.wj). `taint_findings(path)` is the same report for `wj build`, which stops on it. Gate: tests/taint_flow_test.rs over tests/taint/cases (labels `//~ WJ0173`), precision scan in docs/known-gaps.md.
- `tasks.rs` (ADR-0004): WJ0190 for un-waited tasks found by `analyzer::task_structure` (fix: wrap the rest of the block in `scope { }`, machine-applicable for a dropped task) and WJ0191 for removed `thread { }` / `<-` forms the parser records (`parser::task_prefix::RemovedForm`, reported instead of a generic WJ0011); `concurrency_diagnostics` is the subset `wj fix` iterates to a fixed point. Gate: tests/concurrency_surface_test.rs.
- `program_inputs`/`compiler_identity`: the input list and build identity that also key compiled verdicts (`cli/verdict.rs`).

## Owns
Check orchestration, effect findings (`effects.rs`: WJ0040-WJ0048 from `ir::effect_facts`, `durable_sites.rs`: journaled step positions for the interpreter, `wj.toml [capabilities]`/`[policy]`, per-dependency grants via `dep_sources.rs`), file discovery, source locating (`locate.rs`), semantic checks (`semantic/`), result caches (`cache.rs`, `file_cache.rs`, `ambient.rs`), watch loop, fix application.

## Never decides
Diagnostic wording for rustc errors (see `diagnostics/rustc_text.rs`); codegen.

## Allowed imports
Layer `tooling`. Contract: docs/MODULE_MAP.toml; enforced by tests/architecture.rs.

- `shared_cache`: per-file analysis results keyed on content (file text, compiler build key from build.rs `WJ_BUILD_KEY`, `.wj.meta` sidecars by relative name), never on a path, so worktrees share them; the store is injected by `cli::check` (`<cache root>/analysis`). A hit restores the file's own name in its diagnostics. Gate: tests/shared_analysis_cache_test.rs (cached == uncached over the inference corpus and examples; compiler change invalidates).

## Entry points
`check_path`, `check_sources`, `apply_fixes`, `watch::{snapshot, wait_for_change}`; CLI in src/cli/check.rs.

## Tests
Unit tests in `locate.rs`, `files.rs`, `watch.rs`, `semantic/`; tests/diagnostics_suite.rs; tests/check_cache_differential_test.rs (caches).

## Shared analysis
One `program_analysis::ProgramAnalysis` per run (`project::run`; `local_mutability_sources` makes its own): the diagnostics phase, `moves::predict` (the generator receives the shared analyzer and numeric products: `codegen::generate_rust_source_from_products`) and `local_mut::facts::Facts::build` (first pass shared, second pass keyed by the merged files) ask it instead of analyzing again. `WJ_NO_SHARED_ANALYSIS=1` / `WJ_VERIFY_SHARED_ANALYSIS=1` (`check::analysis_mode`) switch it off / verify it; output never changes. Gate: tests/program_analysis_test.rs.

- `ambient.rs`: the run-cache ambient key digests only the `.wj-cache` sidecars the program's `use` segments can reach (`<segment>.wj.meta`, or files in directories named by a segment); unrelated cache files are never listed or read (tests/ambient_cache_dir_test.rs). The key is sidecar content, so an mtime-only touch does not change it.
