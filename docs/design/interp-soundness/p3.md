# P3: inlining calls to user free functions in the JIT: soundness note and decision

> **Rejected design: not implemented.** Inlining mutating free-function calls needs a deopt-inside-the-callee protocol that a perf branch could not carry soundly; the function unit ([fnunit2.md](fnunit2.md)) takes the entry-cost win instead.

Verdict: NOT IMPLEMENTED on this branch. The conditions below are all satisfiable by guards, except one
(deopt inside the callee) whose sound implementation is a new engine protocol, larger than a perf branch can carry
with its test matrix. Branch perf-p3-jit-inline-free-fn stays at the pipeline head (no code).

## What the existing method inline relies on
`inline_call` (lower_struct.rs) inlines only a pure callee: `let`s of scalars/structs plus a tail expression, no
parameter or self mutation (`param_mutation`, `self_mutation`), no statements. Every check inside it exits to the
CALLER statement ("the whole caller statement is the unit of resumption", run_stmt refuses inside frames) and the
closure engine re-runs that statement from scratch. That is sound only because the inlined body has done nothing
visible before a failing check (no stores, no calls).

## Why a free function like `advance(bodies, dt)` is different
`advance` mutates the caller's Vec through its parameter (`bodies[i].vx -= ...`), loops, and has `let`s. A failed check
(bounds, overflow, an element of another shape, a guard on a row view) in iteration k has already committed k-1
iterations of stores. Re-running the caller statement would apply them twice. So the exit must resume INSIDE the callee.

## Guards that are straightforward (argued, would be implemented)
* Aliasing of `&mut`/shared handle args: the callee's parameter is bound to the SAME `Bind::Handle(slot, class)` as the
  caller's argument (no copy, as the walker passes the same Rc); refuse when one handle is passed twice, or a handle
  arg is also reachable under another name in the unit's classification (two views of one Vec go stale after a push).
* Recursion / mutual recursion: refuse a callee already on the inline frame stack; MAX_INLINE depth bound.
* Early `return`, `?`, `break` out of the callee, closures, macros, non-native statements (run_stmt): refuse.
* Panics/traps: every trap is an exit (never a native panic); the engine re-raises it with the callee's location.
* Argument evaluation order: only pure arguments (identifiers, scalar expressions the JIT already proves
  effect-free) are inlined; arguments are evaluated left to right into fresh callee variables BEFORE the callee's
  first statement, in the caller's scope (shadowing: the callee body is lowered in a fresh frame, `lookup` stops at
  the frame base, so no capture of caller names; globals/consts resolve through the interpreter tables, not scopes).
* Params the callee assigns, generic/decorated/async/extern callees, callees whose `&mut` params are rebound: refuse.

## The part that is not cheap: deopt state consistency
At an exit inside the inlined callee, the engine must (1) push a callee frame at `rstack.len()` sized
`CompiledFn.nslots`, with params bound as `bind_params` does (declared widths, handle clones), (2) write the callee's
spilled locals to the CALLEE slots with the CALLEE Reg's slot kinds (Boxed/Plain/Typed), (3) register the frame as
`enter_compiled` does (backtrace, depth, `expect_tail_type`), (4) resume `level()` over the callee Reg's statement
codes at the callee path, (5) run `finish_value`/`leave_compiled` (return value, attach_slot_locals, note_main_err),
(6) continue the CALLER path after the call statement. Exit records need a frame index per spill and per path level,
`in_scope` must span both frames, and `Plan::inlines` must cover depth accounting. Any mistake is invisible on the
happy path and shows only as a wrong panic message, backtrace or stale local. I cannot make that argument convincing
inside this task's budget, and the owner's rule is to stop rather than ship an unconvincing argument.

## Alternative recommended for P3 (smaller, no new frame protocol)
Function-level unit: let a unit cover a callee's whole statement list (lets + loops) entered once per call, so a
call costs 1 OSR entry instead of one per loop (nbody: one entry per call instead of two), and the per-entry costs (row views, spill
buffers) are attacked directly (branch perf-nbody-rows-alloc).
